# Sub-1B Decision Index Core ML conversion status

Snapshot: [Decision Index](https://huggingface.co/spaces/multimodalart/jev-decision-index) revision `8f28be13afeb5bf461ed2235e2931cfa5ecd0891` (2026-09-22). The tracker reports 13 entries below one billion served parameters. Source checkpoint revisions in each toolkit are pinned current snapshots; they are **not** proven to be the exact historical checkpoints that the tracker scored. The tracker runs on an NVIDIA GPU, so its latency numbers do not predict Apple Neural Engine speed.

The table records available Core ML artifacts and the scope actually checked. “Selected parity” means a small set of real requests compared against the pinned native model; it is **not** a full Decision Index result, general accuracy claim, or 2048 comparison. Full decision APIs, wider shapes, compression, and hardware placement remain per-model work unless explicitly documented in each toolkit. [ANE and quantization status](ANE_STATUS.md) summarizes the measured paths and rejected trials.

No full Decision Index reproduction has been run for this set. Existing converted packages are useful engineering previews, not evidence that one model beats the optimized, quantized, ANE-tuned shipped Laya in a fair end-to-end task. The per-model reports describe shape limits, probability differences, compute units, package bytes and license terms. FluidUse's exploratory ten-seed 2048 comparison covers GLiNER2 base and multilingual against GLiClass, not the whole table or the Decision Index suite.

Every published weighted Core ML model page in this table has a root `config.json`. For GLiNER2 small and Verdict it is the exact pinned upstream root config. For Laya English, Kev, Kai, Lex, and Jeff it describes the pinned encoder or base architecture; the trained heads and Core ML runtime are separate. Each page includes `CONFIG_PROVENANCE.md` with the source revision and config SHA-256. GLiClass, GLiNER2 base/multilingual, LFM, and shipped Laya already included their root configs. `python sync-hub-configs.py` checks the eight missing configs against their conversion locks and source hashes; `--upload` adds only the metadata files. A root config does not imply that a Core ML package loads through Transformers AutoModel.
