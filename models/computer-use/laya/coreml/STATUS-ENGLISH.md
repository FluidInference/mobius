## L128 ANE / embedding experiment (2026-09-22)

The shipped multilingual Laya's embedding-only int8 scheme was applied unchanged to this larger English root graph. It reduced the package from **843,174,305 to 791,749,909 bytes** (`reports/english-e8-L128-conversion.json`), but failed the existing 16-question native parity gate on both ALL and forced ANE. ALL retained 16/16 argmax choices yet reached calibrated probability error **0.0590** (gate 0.02); forced ANE reached **0.0523**. The 20-option low-temperature request is most sensitive. On the same fixed fixture, full-request p50/p95 was **8.77/10.12 ms FP16** and **9.09/11.36 ms e8** on ALL. This experiment stays local; the validated English artifact remains FP16 on ALL.

The English FP16 graph has **1,213 of 1,218** operations ANE-eligible under CPU+ANE, but its estimated runtime share is 82.22% ANE / 17.78% CPU. `coreml-cli` measured **9.30 ms CPU+ANE** versus **7.42 ms ALL/GPU** model-call median (10 iterations), consistent with the earlier forced-ANE accuracy and latency finding. The five CPU fallbacks include int32 preprocessing. On the same 16-question fixture, the already shipped multilingual e8 baseline measured **4.10/4.74 ms full-request p50/p95** on ALL; it remained 16/16 in this small comparison with multilingual FP16. All new timing runs were made while this Mac was on battery and are exploratory; compare variants within the same run, not against AC results. See `reports/english-L128-ane-{fallback,timing}.json` and `reports/request-{english,multilingual}-L128-e8-all.json`.
