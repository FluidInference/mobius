# Kev and Jeff Core ML placement probe

Measured September 22, 2026 on an Apple M5 Pro with 24 GB RAM and macOS 27.0. The Mac was **discharging on battery**. Each row is one warmup and two timed rounds over three or four representative, unlabelled requests (six or eight calls total). Timings cover request rendering and tokenization, Core ML prediction, and answer decoding; model load is separate. The p95 is the maximum observation in these tiny samples. These are exploratory local profiles, not cross-device speed claims or Decision Index scores. JSON reports with each request and battery state are in `reports/`.

Kev 0.5B's previously published one-shot runtime failed on an ordinary unlabelled request because it passed it through a training loader that required `label` and `src`. The new reusable `KevCoreML` session uses upstream's serving renderer. Its input arrays are identical to the labelled verification path on three fixtures, and it served those three requests on both compute-unit settings. CPU + Neural Engine chose the same answer as All on all three, but its maximum probability difference was **0.0210282**, exceeding the earlier 0.02 gate. Use All when that probability gate matters; the faster ANE timing does not imply equivalent probability parity. The existing FP16 package is unchanged. Earlier int8 variants failed the 0.02 gate and were not advanced.

A subsequent **embedding-only int8** trial quantized one constant from the same FP16 package, using `quantize.py --precision e8 --source ... --output ...`. On All compute units, `verify.py` compared the resulting local package with the merged trained checkpoint on three selected typed fixtures (Choice, Noul, Choice): **3/3** chosen answers agreed, with probability errors **0.000992**, **0.002626**, and **0.001482** (maximum below the 0.02 gate). The same six unlabelled full-request calls as FP16 All chose the same answers, with a maximum E8-versus-FP16 probability difference of **0.002669**. The 853,903,798-byte package is **13.7% smaller**, but p50/p95 were **9.90/12.57 ms** versus **9.60/10.14 ms** for FP16 All on separate battery-powered passes. The earlier CPU + Neural Engine E8 sample exceeded the parity gate; this new All-compute observation does not clear that setting or establish benchmark quality. This remains a local experimental artifact; no compressed Kev 0.5B weights were uploaded.

Kev 0.6B W8 retained all four typed choices against the source checkpoint with maximum probability error **0.008554** in the conversion validation. In this paired CPU + Neural Engine probe, W8 and FP16 chose the same answer on four requests; their maximum probability difference was **0.008301**. W8 halves package size, but these samples do not establish a speed improvement. A compiled W8 graph assigned 1,958 of 2,165 operations to ANE. Of the 207 operations listed on CPU, 199 are compile-time `constexpr_affine_dequantize`; six int32 boundary operations had about 4.56 ms estimated CPU runtime. Raw operation count is therefore not a residency or latency percentage.

Jeff FP16 was faster with All than forced CPU + Neural Engine on these requests. The All plan reported GPU execution; the forced plan estimated 72.32% runtime on ANE and 27.68% on CPU despite placing 973 of 992 operations on ANE. Its int32 mask/gather boundary contributed about 3.86 ms estimated CPU time. A targeted per-channel int8 package compressed 146 trained embedding/linear constants and reduced size by **47.1%**. It retained all four native checkpoint choices with maximum absolute logit error **0.129469**, below the existing 0.25 fixture gate. Its All p50 was effectively unchanged, while one first-round request raised p95. W8 is a validated local size variant, not a demonstrated speed or quality improvement and has not been uploaded.

At the start of this probe, `coreml-cli` did not accept `.mlpackage` paths for fallback analysis because it tried to save an `.mlmodelc` to the wrong extension. The loader is fixed in this PR to call `coremltools.utils.compile_model` directly; the GLiNER2 small FP16 and embedding-int8 packages were then profiled successfully from `.mlpackage` paths. The Kev/Jeff fallback reports were produced by compiling their existing packages with the same Core ML Tools API, then analyzing the local `.mlmodelc`. Compiled artifacts and package binaries remain ignored.

## Kev 0.5B published serving repair

The existing [FluidInference/kev-0-5b-coreml](https://huggingface.co/FluidInference/kev-0-5b-coreml) repository was updated from revision `9df58dd3f4b3c12b89b30e46c2e520114f3e124d` in two source-only commits: [`62d02e98d424c643f4a69f8905433a670489e187`](https://huggingface.co/FluidInference/kev-0-5b-coreml/commit/62d02e98d424c643f4a69f8905433a670489e187) repaired serving, then [`8624045d193dbb3a6f9a6c8c20932918f8e3854a`](https://huggingface.co/FluidInference/kev-0-5b-coreml/commit/8624045d193dbb3a6f9a6c8c20932918f8e3854a) documented the optional local E8 trial. At the final revision, the SHA-256 hashes match this checkout: `runtime.py` `a36dca37d4ea71289a99babaa5a9c07f2a634650c089d3c91b8fe7bdb6e8791c`; `preprocessing.py` `aabc410719c0c5da9972a612bee8e0428b11e0677c1c585516034c04298a9773`; `README.md` `2197719ecfe4e38295c6f9f0a99bc8a3154e6330cba4749c42240cadb53026d0`; `quantize.py` `0ab1a978042228e8f462fa966b452baeaecc0520c398dfbfcf867e1da8796bb7`; `verify.py` `dea21dd0cc7eba3f2bd81e08d7919cb64bfd0ea2a0ae845f2a1efb4826affdab`. The published FP16 weight blob remains SHA-256 `0e121f9778fd1ddc41a475f3a843aa136ecf2981d4e9976e9f0f848372905411` (989,113,216 bytes).

An unlabelled Choice request through the package downloaded from the old pinned Hub revision returned `risky` at 0.85 confidence with 45 input tokens. The Hub snapshot stored package files as symlinks; direct Core ML compilation from those symlinks failed, while a real-file copy passed. The repaired runtime detects that layout and stages a copy automatically. A second direct request using `KevCoreML(snapshot_path, units="all")` passed with that staging path. Tests cover byte-identical rendering on three fixtures and the symlink-copy behavior. The package weights were not changed or re-uploaded.
